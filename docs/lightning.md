# The lightning path

The terminal promise: a person can point an agent at this repository, supply their purpose and material, and obtain a standalone world whose meaning, presentation and process can be inspected and corrected.

Work backward from that promise. Every necessary link needs evidence and a failure condition. A failed link breaks the terminal claim; upstream results can remain useful. This is a software adaptation of the lightning method, not a transferred scientific proof or a claim of global minimality.

## Strike and bound

The strike covers the complete initial expedition feature set: reading worlds, typed places and choices, attributed sources, atlas and remembered visits, interactive models, project microsites, media and motion, claim review, source presentation, Encounter and workshop edits, checked repository authoring and reproducible publication. The small reader remains available as a narrower template. This is a finite implementation scope, not every possible Temple programme.

## Necessary links

| Link | Obligation | Decisive failure |
| --- | --- | --- |
| L1 Purpose → meaning | Replace identity and content without changing the kernel. | A personal identity or surrounding checkout is still required. |
| L2 Meaning → relations | Entries, choices and sources name declared objects. | A dangling choice or missing source is accepted. |
| L3 Relations → projection | Admitted facts generate pages and ordered styles. | Missing effects or invalid models execute silently. |
| L4 Projection → inspection | Published source snapshots equal owned inputs. | Inspection exposes stale or invented source. |
| L5 Correction → recomposition | Source edits change their output while mechanisms stay stable. | Output becomes an owner or the kernel changes. |
| L6 Repository → independent copy | A new copy builds without its parent project. | A hidden absolute path or package is required. |
| L7 Feature → reusable contract | Each initial feature has a runnable implementation, concrete inputs/effects and behavior checks. | A recipe names a dependency that the created world does not contain. |
| L8 Agent context → different world | A fresh agent builds a different world using the repository alone. | The build needs hidden source, implementation hints or changes to the native seed. |

## Test and recompose

The suites check generation, invalid references and effects, source disclosure, copied mechanisms, source corrections, finite-model and programme correspondence, session edits/refusals, atlas storage behavior and standalone creation. The extraction verifier binds all 36 initial modules to their actual source/runtime closure. The separate-agent trial tests repository-only authoring of Tidepool Commons and records browser observations. context/lightning.json connects the links to the resulting evidence.

The trial's briefing and acceptance criteria were fixed in context/agent-trial-protocol.json before the agent began. A separate same-model agent is useful transfer evidence; it does not answer whether an outside human finds the system understandable or useful. Human usability remains unobserved.

## Correct

Reopen the earliest affected link. Keep the working reader while extracting a map that needs storage. Revise the composition when another person’s world needs a different shape. Preserve alternatives and useful upstream work.
