# From purpose to a working world

The person’s purpose leads. Worldwright gives that purpose explicit meaning, relations, composition and projection, with context for a person or agent to inspect and change it.

```text
Human purpose and attributed content
  → REL facts: identity, places, choices and sources
  → process algebra: validation, selection and composition
  → admission: model, effects and source ownership
  → unchanged Temple execution
  → HTML and CSS projection
  → source snapshots, build receipt and observed checks
```

## Four editable concerns

Meaning belongs in source/world.rel. Identity stays distinct from visible title. Relations name exact destinations and source objects.

Composition and policy belong in algebra/world.process.json. Validation runs before page projection. Add process modules to bootstrap/site.json with their complete call closure and required facts.

Presentation belongs in source/presentation.rel and the CSS algebra. Rule order is explicit. Generated styles have one authoring chain.

Mechanisms belong in bootstrap. Filesystem observation, strings and browser effects are native ports. Algebra chooses what to do with them. An available mechanism is not automatically a permitted effect.

## What a template means

templates/world is an executable standalone world. templates/feature.json is the common extension contract: purpose, types, invariants, owners, dependencies, effects, projections, correction, verification and missing edges. It can describe a reader, map, model, editor, source inspector or publication process without inventing a second interpreter.

The contract can express a feature before its implementation is portable. Status must preserve that distinction. reference/algebra is the attributed initial library. context/features.json inventories every module, named query, derived operator, literal call and port. Computed dispatch and semantic dependencies still need inspection.

## Reading and changing are different

Source snapshots expose definitions. Receipts record hashes and execution use. Neither is a live trace. A checked editing feature must declare its owner and route, check the source version, validate the candidate and compare its forward projection before acceptance. Never infer a universal inverse from a rendered string.

Aaron’s implementation includes checked authoring and an Encounter example; these remain reference extractions here. The first-world starter uses ordinary source edits followed by a checked build.

## The hub and the world

Worldwright.io begins with the introduction and continues into docs, the example, the catalogue and machine-readable context. Aaron’s site remains the initial personal world. The hub’s Markdown renderer is an explicit native publishing tool; the example is generated through Temple algebra. Full algebraic self-hosting of the hub remains open.

## Evidence boundaries

source/upstream.json pins exact copied mechanism hashes. Local tests form one evidence family. They support this bounded implementation, not scientific truth, independent verification or a globally complete or minimal algebra.
